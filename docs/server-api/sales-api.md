# Sales API — витрина цен для сайта продаж

Server version: 0.86.0

Аудитория: **сайт продаж** (dmlab_server, внешний проект «Site DML»). Канал доставки
контракта — ручной ANNOUNCE (dmlab вне SDH-синка, см. CLAUDE.md «Cross-repo канал
с dmlab_server»); файл в `docs/my_api/` — источник истины.

## Access model

S2S shared-секрет, вне двухключевой auth-цепочки:

- Заголовок **`X-Sales-Key: <секрет>`** на каждый запрос. Сравнение constant-time.
- Секрет генерится сервером (server_config `sales.s2s_secret`, сид миграцией),
  передаётся администратором вручную. Ротация — `PUT /v1/admin/config` (после
  ротации старое значение перестаёт действовать сразу; новое передать сайту руками).
- Секрет пуст в конфиге → эндпоинт отключён.

Ошибки доступа:

- `SALES_DISABLED` (403) — секрет не настроен на сервере (эндпоинт выключен)
- `SALES_KEY_INVALID` (403) — заголовок отсутствует или не совпал

## Endpoints

#### `GET /v1/s2s/sales/models`
Витрина моделей с боевыми ценами продажи. Отдаются только модели, которым
администратор задал `tier` (см. «Управление составом» ниже) и у которых есть
строка внутреннего прайса.

**Request:** без тела, только заголовок `X-Sales-Key`.

**Response (200):**
```json
{
  "serviceInfo": "(standard)",
  "models": [
    {
      "id": "string, канонический model id (vendor/name), технический",
      "displayName": "string, человекочитаемое имя для витрины",
      "description": "string, optional (omitempty) — маркетинговое описание в дефолт-локали ru (= descriptionI18n.ru; legacy-ключ, сохранён для обратной совместимости)",
      "descriptionI18n": "object, optional (omitempty) — локализованные описания, напр. {\"ru\": \"…\", \"en\": \"…\"} (v0.85.0)",
      "tier": "string, enum: flagship | advanced | balanced | basic",
      "pricesPer1M": {
        "input": "int, коины за 1М входных токенов",
        "output": "int, коины за 1М выходных токенов",
        "cacheRead": "int, коины за 1М токенов кэш-чтения",
        "cacheWrite": "int, коины за 1М токенов кэш-записи"
      }
    }
  ]
}
```

- `models` — всегда массив (пустой состав → `[]`, не `null`).
- **Локализация описаний (T-000341, v0.85.0):** дефолт-локаль — **`ru`**. Ключ
  локали в `descriptionI18n` присутствует ⟺ описание в этой локали непусто:
  **отсутствие ключа ≠ пустая строка** — при отсутствии `en` сайт фолбэчит на
  `ru`. Состав моделей, `id`, `tier` и цены от локали **не зависят**. Legacy-ключ
  `description` остаётся навсегда и равен `descriptionI18n.ru`.
- **Подпись уровня (`tier`) не локализуется сервером** — отдаётся машинный
  enum-код; текст бейджа на каждом языке — зона сайта.
- Порядок — по цене входа по убыванию (стабильный дефолт; сортировка на витрине — на стороне сайта).
- `tier` → русские бейджи рендерит сайт: `flagship` = «Флагманская»,
  `advanced` = «Продвинутая», `balanced` = «Сбалансированная»,
  `basic` = «Базовая» (v0.84.1).
- Цены — **целые коины за 1 000 000 токенов**, уже конечные цены продажи
  (пересчёт в ₽ — по курсу коина, который сайт знает из своей конфигурации).
- Кэш-цены: `cacheRead` — чтение из кэша контекста (сильно дешевле входа),
  `cacheWrite` — запись в кэш (дороже входа).

**Errors:**
- `SALES_DISABLED` / `SALES_KEY_INVALID` (403) — см. Access model
- `DB_ERROR` (500) — внутренняя ошибка чтения

**Side effects:** нет (read-only).

## Управление составом витрины (для администратора, справочно)

Состав и тексты витрины управляются через admin API сервера
(`PUT /v1/admin/model-display-overrides/{modelId}` — displayName, description,
tier; см. admin-api-pricing.md). Модель показывается на витрине, пока у неё
задан `tier`; сброс `tier` в `""` снимает модель с витрины. Цены приходят из
внутреннего прайса сервера и меняются его же механизмами (refresh-sell / admin
PUT model-prices) — сайту для актуализации достаточно периодически перечитывать
эндпоинт.
